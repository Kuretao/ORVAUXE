# Edition Client Readiness

This checklist determines when an ORVAUXE Edition project reaches **Ready to Build**. It protects the client’s 7–10-business-day target by separating sales and preparation time from implementation time.

## Readiness owners

- ORVAUXE confirms scope, technical fit, dependencies and access sufficiency.
- The client names one responsible feedback owner who can provide consolidated decisions.
- The client confirms that supplied assets and content are approved for use and that required font/media licenses exist.
- Both parties record the Ready to Build date after every required item below is complete.

## Brand

- [ ] Approved logo files supplied in usable formats.
- [ ] Approved color specifications supplied.
- [ ] Approved typography identified.
- [ ] Web font files or service access supplied where needed, with appropriate licenses confirmed by the client.
- [ ] Brand guidelines supplied if available.
- [ ] Any non-negotiable brand-use constraints identified.

## Content

- [ ] Approved homepage and supporting-page copy supplied.
- [ ] Approved product titles and descriptions supplied.
- [ ] Approved collection names and descriptions supplied.
- [ ] Legal and policy copy supplied or confirmed in Shopify.
- [ ] Contact details, social links and navigation labels supplied.
- [ ] Editorial/About content supplied for the agreed page.

ORVAUXE can format and integrate approved supplied copy within the Edition. Copywriting and legal drafting are not part of the base scope.

## Commerce

- [ ] Products for the initial launch scope exist or are supplied in the agreed import format.
- [ ] Prices are approved.
- [ ] Variants and option names are approved.
- [ ] Collections and merchandising order are approved.
- [ ] Inventory expectations and out-of-stock behavior are confirmed.
- [ ] Initial language, market and core currency/store setup are confirmed.
- [ ] Shipping, tax, payment and policy dependencies owned by the merchant are sufficiently configured for agreed QA.

Complex catalog cleanup, business configuration and bulk data entry require separate scope.

## Media

- [ ] Product photography supplied at usable quality and aspect ratios.
- [ ] Campaign photography supplied where the selected Edition composition requires it.
- [ ] Editorial imagery supplied for the agreed pages.
- [ ] Image usage rights confirmed by the client.
- [ ] Alt-text source information or product context supplied where ORVAUXE cannot infer it accurately.

Missing campaign or product imagery can materially change the Edition’s result and pauses readiness unless an approved replacement plan is included in scope.

## Access

- [ ] Appropriate Shopify collaborator, staff or development-store access provided.
- [ ] Theme permissions sufficient for the agreed implementation and preview workflow.
- [ ] Domain or DNS access available when included in launch scope.
- [ ] Required third-party app or account access available when explicitly in scope.
- [ ] A secure credential-transfer method agreed; credentials are not stored in product documentation or the theme repository.

## Scope, commercial and approval

- [ ] Selected Edition and base version recorded.
- [ ] Deliverables, exclusions and any approved add-ons recorded.
- [ ] Required payment or deposit complete.
- [ ] One responsible client feedback owner named.
- [ ] Client agrees to provide one consolidated package per revision round.
- [ ] Approval path and expected response times confirmed.
- [ ] Launch/publishing authority identified.

## Ready to Build sign-off

A project is **Ready to Build** only when all of the following are true:

| Gate         | Required evidence                                                |
| ------------ | ---------------------------------------------------------------- |
| Scope        | Approved Edition, deliverables, exclusions and add-ons           |
| Commercial   | Required payment/deposit confirmed                               |
| Platform     | Shopify access and necessary permissions verified                |
| Brand        | Approved logo, palette, typography and licensing inputs received |
| Content      | Required copy, product data and legal/policy inputs received     |
| Media        | Required product, campaign and editorial assets received         |
| Integrations | In-scope third-party dependencies and credentials available      |
| Approval     | One feedback owner and required approvals confirmed              |

Record:

- Client/store: `____________________`
- Edition and base version: `____________________`
- Approved scope reference: `____________________`
- Responsible feedback owner: `____________________`
- Ready to Build date: `____________________`
- ORVAUXE confirmation: `____________________`
- Client confirmation: `____________________`

Blank fields are intentional; this is a reusable readiness template, not a completed client record.

## Clock and change control

The target delivery clock starts on the recorded Ready to Build date. It pauses when required input, access, credentials or approval becomes unavailable, or when the client replaces an approved input in a way that blocks dependent work.

An out-of-scope request is classified under [Editions vs Atelier](./editions-vs-atelier.md). An approved add-on records its commercial and schedule effect before implementation resumes. The delivery target is not a promise measured from first contact, proposal issue or deposit alone.
